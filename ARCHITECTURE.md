# Авитолог: обмен через личный репозиторий

## Назначение

Приватный репозиторий служит очередью между сайтом на телефоне и обработчиком на рабочем компьютере. Сайт не обращается к компьютеру напрямую, поэтому ему не нужен публичный IP, домен или туннель.

Ключ вводится пользователем только на его устройстве и хранится в браузере этого устройства. В исходный код сайта, коммиты и ответы обработчика ключ не попадает.

## Папки очереди

```text
inbox/     новые действия с сайта и временные вложения
outbox/    короткие результаты обработки для сайта
state/     компактное актуальное состояние без оригинальных фото
audit/     текстовый журнал, разбитый по месяцам
```

`inbox` и `outbox` не являются архивом. Обработчик после подтверждённой обработки удаляет исходное сообщение и временные вложения. В `state` остаётся только последнее состояние объявления, календаря и указателей обработки. В `audit` остаются только текстовые события, а старые месяцы выгружаются и очищаются по расписанию.

## События

Каждый файл события содержит `id`, `type`, `createdAt` и `payload`.

| Направление | События |
|---|---|
| Сайт → обработчик | `item.created`, `item.edited`, `item.comment`, `item.publish`, `item.status`, `item.deleted`, `cards.requested` |
| Календарь → обработчик | `calendar.slot.opened`, `calendar.slot.removed`, `calendar.booking.created`, `calendar.booking.cancelled` |
| Обработчик → сайт | `listing.ready`, `chat.upsert`, `offer.upsert`, `item.status` |

`chat.upsert` содержит только текстовую ленту, имя собеседника и короткую сводку. Фото и видео из переписок в репозиторий не копируются.

## Фото и размер репозитория

Оригиналы не считаются постоянным хранилищем. Они передаются в `inbox` только для обработки и удаляются после успешного ответа. Для опубликованных объявлений обработчик получает фото повторно по ссылке или через API площадки, когда это потребуется.

Обычное удаление файла из GitHub не стирает его из истории коммитов. Поэтому в очереди нельзя держать видео, большие фото или бессрочные архивы. Для чистого роста используются только небольшие временные файлы, а рабочая очередь регулярно переносится в новый приватный репозиторий. Если позже понадобится хранить оригиналы, для них нужен отдельный объектный storage, а не GitHub.

## Обработчик на рабочем компьютере

1. Раз в несколько секунд читает новые файлы `inbox`.
2. Проверяет `id` по `state/cursors.json`, чтобы не обработать событие дважды.
3. Забирает временные вложения только для текущей задачи.
4. Записывает короткий результат в `outbox` и обновляет `state`.
5. Удаляет обработанные файлы `inbox` после успешной записи результата.

Этот процесс запускается на рабочем компьютере, где будет работать Авито и обработчик. Текущий компьютер остаётся только средой проверки и не требует автозапуска или фоновой службы.
