# Авитолог: обмен через личный репозиторий

## Назначение

Приватный репозиторий служит очередью между сайтом на телефоне и обработчиком на рабочем компьютере. Сайт не обращается к компьютеру напрямую, поэтому ему не нужен публичный IP, домен или туннель.

Ключ вводится пользователем только на его устройстве и хранится в браузере этого устройства. В исходный код сайта, коммиты и ответы обработчика ключ не попадает.

## Одноразовый репозиторий месяца

Весь обмен идёт через GitHub: фото, видео, объявления, календарь, переписки и результаты. Для каждого авитолога и каждого месяца приложение использует отдельный приватный репозиторий:

```text
avitolog-<идентификатор>-2026-10
avitolog-<идентификатор>-2026-11
```

В начале месяца приложение создаёт новый репозиторий, создаёт его папки и сохраняет его как активную очередь. Предыдущая очередь принимает только уже начатые задачи. Когда обработчик подтвердил, что в ней нет незавершённых задач, приложение удаляет старый репозиторий целиком, а не отдельные файлы.

У каждого авитолога — свой GitHub-аккаунт и отдельная последовательность приватных репозиториев. Название содержит случайный идентификатор авитолога и месяц, чтобы очереди не пересекались.

## Папки активной очереди

```text
inbox/     новые действия с сайта и временные вложения
outbox/    короткие результаты обработки для сайта
state/     компактное состояние текущего месяца
audit/     текстовый журнал текущего месяца
```

`inbox` и `outbox` не являются архивом. Обработчик после подтверждённой обработки удаляет исходное сообщение и временные вложения. В `state` остаётся только последнее состояние объявления, календаря и указателей обработки. В конце месяца удаляется весь репозиторий с его историей очереди.

## События

Каждый файл события содержит `id`, `type`, `createdAt` и `payload`.

| Направление | События |
|---|---|
| Сайт → обработчик | `item.created`, `item.edited`, `item.comment`, `item.publish`, `item.status`, `item.deleted`, `cards.requested` |
| Календарь → обработчик | `calendar.slot.opened`, `calendar.slot.removed`, `calendar.booking.created`, `calendar.booking.cancelled` |
| Обработчик → сайт | `listing.ready`, `chat.upsert`, `offer.upsert`, `item.status` |

`chat.upsert` содержит текстовую ленту, имя собеседника и короткую сводку. Вложения передаются через `inbox` как временные файлы, когда это нужно задаче.

## Фото и размер репозитория

Оригиналы передаются в `inbox` только для обработки и удаляются после успешного ответа. Они не переносятся в следующий месячный репозиторий. Сайт получает из `outbox` только нужный результат обработки.

Обычное удаление файла не очищает историю текущего репозитория. Поэтому очередь меняется целиком: каждый месяц создаётся новый репозиторий, а завершённый удаляется целиком. Так активная очередь не растёт годами и не содержит файлы прошлого периода.

## Права ключа

Ключ авитолога хранится только в браузере его устройства. Для этой схемы ему нужны права на создание приватного репозитория, работу с его содержимым и удаление завершённого репозитория. Сайт применяет ключ только к репозиториям с префиксом `avitolog-<идентификатор>-`.

## Обработчик на рабочем компьютере

1. Раз в несколько секунд читает новые файлы `inbox`.
2. Проверяет `id` по `state/cursors.json`, чтобы не обработать событие дважды.
3. Забирает временные вложения только для текущей задачи.
4. Записывает короткий результат в `outbox` и обновляет `state`.
5. Удаляет обработанные файлы `inbox` после успешной записи результата.

Этот процесс запускается на рабочем компьютере, где будет работать Авито и обработчик. Текущий компьютер остаётся только средой проверки и не требует автозапуска или фоновой службы.
