# Авитолог: очередь, локальный обработчик и сайт

## Назначение

Приватный GitHub-репозиторий служит очередью между сайтом на телефоне и рабочим компьютером. Сайт не подключается к компьютеру напрямую, поэтому для этой части системы не нужен публичный IP, домен или туннель.

Секретный ключ вводится на устройстве пользователя и хранится только в браузере этого устройства. Он не попадает в исходный код, коммиты, события или ответы обработчика.

## Репозиторий текущего месяца

Каждый авитолог использует свой приватный репозиторий на текущий месяц. В день ежемесячного продления репозиторий меняется вручную:

```text
avitolog-<идентификатор>-2026-10
avitolog-<идентификатор>-2026-11
```

Старый репозиторий удаляется только после того, как все его задания завершены. Это удерживает активную очередь небольшой: фото и временные файлы не накапливаются годами.

## Папки репозитория

```text
inbox/     новые действия сайта и временные вложения
outbox/    результаты обработчика для сайта
state/     компактный снимок объявлений, календаря и указателей обработки
audit/     журнал текущего месяца без ключей и токенов
```

## Формат событий

Каждое событие использует схему `avitolog.mailbox.v1` и содержит уникальный `id`, `type`, `createdAt`, `payload` и `markers`.

```json
{
  "schema": "avitolog.mailbox.v1",
  "type": "cards.requested",
  "markers": {
    "origin": "site",
    "action": "cards.generate",
    "listingId": "…",
    "cards": {"requested": true, "style": "realistic", "count": 3}
  }
}
```

Маркеры однозначно сообщают обработчику, нужны ли карточки, какой выбран стиль и сколько вариантов нужно подготовить.

| Направление | События |
|---|---|
| Сайт → обработчик | `item.created`, `item.edited`, `item.comment`, `item.publish`, `item.status`, `item.deleted`, `cards.requested` |
| Календарь → обработчик | `calendar.slot.opened`, `calendar.slot.removed`, `calendar.booking.created`, `calendar.booking.cancelled` |
| Обработчик → сайт | `listing.ready`, `item.status`, `chat.upsert`, `offer.upsert`, `analytics.snapshot` |

Сайт записывает объявления с устойчивым именем события. При повторной отправке после сбоя он обновляет тот же файл, поэтому одно действие не создаёт вторую задачу. Обработчик дополнительно проверяет уникальный `id` перед выполнением.

## Синхронизация сайта

После каждого изменения сайт немедленно отправляет новые действия в `inbox` и обновляет `state/site-state.json`. Сайт получает результаты из `outbox` при открытии, после собственного действия и каждые пять минут. Снимок состояния объединяет изменения с двух устройств по времени последнего изменения; удалённые объявления не возвращаются при более поздней синхронизации.

Оригиналы фото передаются только для создания или ручного изменения объявления. Снимок состояния хранит уменьшенный предпросмотр, чтобы карточка не теряла изображение на втором устройстве.

## Локальный обработчик на рабочем компьютере

| Проверка | Период |
|---|---:|
| Новые чаты Avito API | 2 минуты |
| Новые предложения | Определяются при обработке новых чатов |
| Приватная очередь GitHub | 60 минут |
| Статистика опубликованных объявлений | 6 часов |

Обработчик выполняет порядок: читает задание → проверяет `id` → забирает нужные вложения → собирает правила и контекст → вызывает Codex только для новой смысловой задачи → проверяет результат → выполняет разрешённое действие Avito API → пишет результат в `outbox` → удаляет исходное задание из `inbox`.

При отсутствии новой задачи Codex не запускается. При ошибке событие остаётся в очереди и повторяется с тем же `id`.

## Аналитика

Avito API-ключ находится только на рабочем компьютере. Раз в шесть часов обработчик формирует `analytics.snapshot` и кладёт его в `outbox`. Сайт отображает просмотры, избранное, переписки и предложения, но не делает прямых запросов к Avito.

## MCP

MCP не передаёт объявления между телефоном и компьютером. При необходимости он подключается локально к Codex как набор инструментов для файлов и сервисов.
