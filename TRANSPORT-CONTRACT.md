# Контракт быстрого транспорта v2

Этот документ описывает обмен между сайтом, приватным hub-репозиторием и отдельным репозиторием объявления. Он не содержит ключей, ссылок на реальные объявления или пользовательских данных.

## Неизменяемые правила

- `taskId` неизменен от создания задания до результата. Повторная доставка той же команды не создаёт вторую обработку.
- Для задания сначала сохраняется `listing.json` и обязательные новые медиа в репозитории объявления. Только затем создаётся файл задания и команда в `hub/inbox`.
- Фотографии не прикладываются к каждой команде. В v2 задача содержит ссылки `path`/`file` на уже сохранённые оригиналы объявления.
- Комментарий и правка текста не передают изображений. Новая серия карточек использует только оригиналы из `listing.json`.
- Команда считается доставленной только после чтения обратно того же hub-файла с совпадающими `taskId` и `itemRepository`.
- Удалённое объявление не обрабатывается даже при запоздавшей команде.

## Формат команды hub

```json
{
  "schema": "avitolog.hub-command.v1",
  "transportVersion": 2,
  "taskId": "stable-task-id",
  "listingId": "listing-id",
  "type": "cards.requested",
  "createdAt": "ISO-8601",
  "itemRepository": "owner/listing-repository",
  "taskPath": "tasks/in/stable-task-id.json"
}
```

Версия 1 остаётся допустимой для уже сохранённых команд. Версия, отличная от 1 или 2, явно отклоняется обработчиком и записывается в технический журнал.

## Формат задания

Файл `tasks/in/<taskId>.json` использует прежний контейнер `avitolog.task.v1`; его `input` содержит событие `avitolog.mailbox.v1` с `transportVersion: 2`. Для фото доступны `id`, `name`, `type`, `file`/`path`, необязательные `blobSha` и `size`. `data:`-строки в задачу не попадают.

Старый формат с именами вложений из `tasks/in` по-прежнему читается. Новые задания не создают такие дубликаты.

## Порядок и восстановление

1. Сайт сохраняет локальную очередь и медиа.
2. Сайт создаёт или обновляет минимальный снимок объявления.
3. Сайт обновляет строку реестра.
4. Сайт записывает файл задания в репозиторий объявления.
5. Сайт добавляет команду в `hub/inbox` и перечитывает её.
6. Обработчик публикует `listing.json`, результаты и `hub/outbox` с checkpoint для восстановления после обрыва.

При сетевом сбое повторяется только незавершённый шаг. Повторная попытка не копирует ранее подтверждённые оригиналы и не создаёт новую серию карточек.
