# Авитолог: интерфейс и подключение

Опубликованная версия: https://investicii917-wq.github.io/avitolog-dashboard/

## Текущий режим

Статическое приложение в docs/ работает без исходящих запросов к MCP и Avito. Объявления, исходные фотографии, комментарии, предложения, интервалы и встречи сохраняются в IndexedDB этого браузера. Состояние не синхронизируется между устройствами. Очистка данных сайта удаляет его. Вход сохраняется в localStorage. Пароль на статической странице — только блокировка интерфейса, не серверная защита; перед реальным подключением нужна серверная авторизация.

## Экраны

- /analytics — пустая аналитика до первых событий MCP; /list/ready и /list/published — рабочие списки.
- /new — создание с 0–10 оригинальными фото и необязательной ценой.
- /item/:id — галерея, поля и действия объявления.
- /item/:id/edit — ручное редактирование фото, текста, цены, доставки и времени получения.
- /item/:id/comments — история и новые комментарии для обработки.
- /item/:id/offers — предложения с датами, способом получения и числом сообщений.
- /item/:id/book/:offerId — встреча внутри открытых окон с проверкой занятости.
- /calendar — месяцы, доступность и загруженность по длительности встреч.
- /slot/new?date=YYYY-MM-DD — открытие времени.
- /slot/:id — расписание интервала.

Маршруты идут после # в адресе, поэтому поддерживаются прямые ссылки и кнопка «Назад» на GitHub Pages.

## Граница данных для будущего MCP

model.js содержит чистую обработку событий. data.js — адаптер хранения. app.js использует их вместо жёстко зашитых карточек. Начальное состояние всегда пустое: товары, фото, предложения, встречи, статистика и черновики появляются только после ручного ввода или событий MCP. Повторное событие с тем же id не дублирует данные.

В открытом авторизованном браузере доступен window.avitologBridge.receive(event). Это локальный вход для интеграции, не публичный HTTP endpoint. Никакой URL транспорта не задан. Когда будет известен формат MCP, серверный адаптер должен авторизовать и валидировать события, затем передавать их интерфейсу. Ключи Avito должны оставаться только на сервере.

Пример события:

    {"id":"unique-event-id","type":"item.upsert","payload":{"id":"gym-20","status":"ready","title":"Тренажёр","price":20000,"photos":[],"pickupMinutes":60,"delivery":false}}

Поддержаны item.upsert и offer.upsert; поля формата видны в model.js. События изменения, комментария и локальной публикации складываются в outbox. Они сейчас никуда не отправляются. Кнопка публикации меняет только локальный этап; реальное подтверждение Avito должен обработать будущий адаптер.

public/ содержит ту же браузерную версию. Старый server.js остаётся отдельным каркасом REST/SQLite; он ещё не соединён с новым адаптером данных и не используется GitHub Pages.
