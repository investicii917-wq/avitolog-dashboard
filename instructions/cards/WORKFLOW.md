# Процесс производства серии

## 1. Паспорт и доказательства

Сохранить исходные файлы без перезаписи. Выписать название, разновидность, бренд/модель если они читаемы, состояние, комплект, количество, размеры, материалы, цвет, ограничения, пожелания, цену. У каждого факта — источник: поле объявления, цитата заметки, конкретная фотография или проверенная спецификация именно этой модели. Не определять механизм клавиатуры, водозащиту, ресурс, размеры и совместимость по внешности.

Собрать таблицу: факт → потребность покупателя → честный тезис → подтверждение → кадр. «Есть цифровой блок» можно показать на фото; «ускоряет работу вдвое» нельзя выводить из этого факта. Неизвестное исключить из плашек. Не превращать пожелания продавца в свойства товара.

Сопоставить описание с фотографией. Если конфликт существенный (другая модель, цвет, число единиц), остановить спорную часть и запросить уточнение. Пустое описание не ломает транспорт: можно создать фото без заявлений либо дизайнерский кадр с доказуемыми видимыми фактами; недостаток данных отметить.

## 2. Профиль серии

Выбрать стиль только из задания. Определить категорию, форму, ценовой контекст относительно своей категории, риск покупки и главное возражение. Зафиксировать canvas: 1600×1200 для 4:3 или 1200×1600 для 3:4 как рабочий ориентир. Допустим другой размер при точной пропорции и достаточной детализации. Пропорция задаётся один раз для всех кадров этого товара.

Зафиксировать два-три цвета из товара и нейтральный фон, одно-два семейства шрифтов, одинаковые поля и систему подписи. Домашний и студийный стили обходятся без рекламного текста; дизайнерский строится на проверенной студийной основе. Для чувствительной геометрии/надписей использовать композицию с сохранённым исходным предметом, если выбранный инструмент это позволяет; генеративную перерисовку нельзя принимать как точную копию автоматически.

## 3. Раскадровка по количеству

| Количество | Содержание |
|---|---|
| 1 | Сильный понятный общий вид, предмет целиком |
| 2 | Общий вид + самый важный подтверждённый аспект |
| 3 | Обложка + функциональная деталь + второй вопрос/деталь/контекст |
| 4–5 | Добавить подтверждённые размеры/комплект/состояние, если есть исходные данные |
| 6–10 | Дополнительные доступные ракурсы, материалы, крепления, варианты использования, дефекты, схема выбора; без пустых повторов |

Это порядок выбора сюжетов, не обязанность заполнять неизвестное. Для каждого кадра записать роль, источник фото, допустимое кадрирование, факты, текст, ограничения и критерий приёмки. Нельзя подменять разные ракурсы одинаковыми изображениями с другими заголовками. Если есть только лицевая фотография, допустимы общий план и крупные планы видимых деталей; тыл, разъёмы, интерьер дома, багажник машины неизвестны. Не выдавать воображаемый ракурс за реальный. Если count невозможно наполнить достоверно — needs_input с перечнем нужных фото.

## 4. Генерация и сборка

Для realistic/studio — отдельное задание на каждый кадр с исходником и одним описанием серии. Следующие кадры сверять с оригиналом, а не последовательно перерисовывать предыдущий: иначе ошибки накапливаются.

Для designer — сначала студийные основы, прошедшие проверку товара; затем оформить каждую под её сюжет. Сохранить связи `sourcePhotoId → studioAssetId → designerAssetId`. Не использовать студийный вариант с неправильной геометрией или надписями. Если текстовый движок надёжнее генератора, собрать типографику им с разрешения пользователя на такой способ; не выдавать кодовый коллаж за результат генератора.

Не добавлять без основания знак качества, сертификат, рейтинг, отзывы, значок продажи миллионами, скидку, срок службы, гарантию, ограниченный остаток. Для бывшего в употреблении товара сохранять реальные следы эксплуатации. Не создавать рекламу, обещающую то, чего продавец не подтвердил.

## 5. Приёмка и передача

Проверить каждый файл и всю серию по QA. Сохранить исходники и принятые результаты отдельно. Результат локально — манифест, изображения, краткое пояснение выбранного визуального решения и открытые вопросы. На GitHub — файлы результата и событие согласно CONTRACT. Сайт не должен показывать «готово», пока файл существует только в каталоге генератора и ещё не передан.


## Обязательное правило обложки — 2026-10-17
Это уточнение заменяет прежнее требование одинаковых пропорций ВСЕХ файлов. Первая карточка всегда физически квадратная (1:1, width=height). Вторая и следующие — все 4:3 или все 3:4 по выбранному формату. При auto выбрать формат только для карточек 2..N. При count=1 выдать только квадратную обложку. Число включает обложку. Не менять выбранный домашний/студийный/дизайнерский стиль. Все важные детали и надписи должны помещаться внутри кадра без обрезания. Обложка должна привлекать внимание честной композицией, без выдуманных свойств. Результат передаёт реальные width/height каждой карточки, coverAspectRatio=1:1 и aspectRatio для остальных.
