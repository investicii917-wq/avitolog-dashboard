# Контракт сайта и обработчика

Дополнение к действующему `avitolog.mailbox.v1`, версия блока cards — 2. Существующие объявления без новых полей читаются: `realistic`, количество 1, формат auto. Не переименовывать историческое значение realistic в home в JSON.

## Движение

```text
Форма: стиль + число + формат + фото + заметки
  → локальное сохранение → inbox/*-text.txt и его вложения
  → локальный обработчик: получить cards.requested, захватить событие
  → facts.json / shot-plan.json / генерация / проверка
  → outbox/<время>-<requestId>-01.png ...
  → outbox/<время>-<requestId>-result.json с cards.completed
  → сайт при синхронизации показывает готовые фото
```

Вложение загружается раньше манифеста задания; изображения результата — раньше результата. На промежуточном сбое итоговый манифест не публикуется. Пути вложений в JSON относительно inbox или outbox, без `..`, URL, дисков и абсолютных путей. Ключи доступа в файлы не включать.

## Вход

Событие `cards.requested`: `id` — идентификатор события, `payload.requestId` — запрос, `payload.itemId`, `payload.item` — снимок объявления; `payload.photoIds`, `payload.requestKey`, `payload.style`, `payload.count`, `payload.format`, `payload.aspectRatio`. `markers.action=cards.generate`, `markers.cards` дублирует параметры. Если блоки расходятся — ошибка контракта, не угадывать.

`markers.cards`: `contractVersion:2`, `requested:true`, `style:realistic|studio|designer`, `count:1..10`, `format:auto|landscape|portrait`, `aspectRatio:null|4:3|3:4`, `uniformAspectRatio:true`, `baseStyle:studio` только для designer, `preserveProduct:true`, `factsSource:listing.description-and-notes`, `guide:instructions/cards/README.md`.

Отдельное `item.created`/`item.edited` сохраняет объявление. Если вместе приходит cards.requested, не генерировать дважды по двум событиям. Генерацию запускает cards.requested; флаг в снимке — намерение и состояние UI.

`requestKey` — непрозрачная строка, которую сайт строит из настроек, описания, цены, состояния и идентификаторов исходников. Копировать буквально, не пересчитывать алгоритмом другой версии. Локально можно хешировать её для имени папки. Смена фото/текста/стиля/количества/формата создаёт другое задание. Повторное сохранение без изменений — не новое задание.

## Ответ

```json
{
 "schema":"avitolog.mailbox.v1",
 "id":"unique-result-id",
 "type":"cards.completed",
 "createdAt":"2026-10-13T10:00:00Z",
 "sourceEventId":"original-event-id",
 "payload":{
   "itemId":"listing-id",
   "requestId":"original-request-id",
   "requestKey":"EXACT_INPUT_STRING",
   "style":"designer",
   "aspectRatio":"4:3",
   "photos":[
     {"id":"unique-photo-id","name":"Общий вид","file":"20261013100000-request-01.png","type":"image/png","width":1600,"height":1200}
   ]
 }
}
```

Число photos равно запрошенному count, порядок задаёт сюжет. Все изображения одной пропорции; размер считать по самому файлу, не по желаемому промпту. Имена уникальны; старые результаты не перезаписывать. До доставки обработчик сохраняет локальную запись с sourceEventId/requestId/requestKey и SHA-256 файлов. При повторе API сверяет уже отправленные имена и хеши.

Сайт принимает результат только для текущего requestKey, стиля, количества и формата. Исходники сохраняются отдельно в sourcePhotos; карточки становятся галереей. `cards.completed` не переводит объявление в опубликованные и не меняет цену. Подготовка текста объявления возвращается существующим `listing.ready` отдельно.

Ошибки: `needs_input` только при отсутствии пригодного исходника, нераспознаваемом предмете или существенном противоречии источников; число исходных фото меньше `count` не является ошибкой и не уменьшает число результата. `quality_failed` — при изменении товара, `retryable_error` — при сети, `quota_exhausted` — при лимите. Обработчик использует доступные исходники как референс и возвращает полную серию ровно из `count` файлов. Ошибки регистрирует обработчик в своём журнале; не выдавать cards.completed для неполной серии. После лимита не гонять бесконечные повторы. Если картинка создана, но CLI не вернул JSON, сначала сверить артефакты именно того сеанса, затем решать о повторе.

Готовый сервер-обработчик этой инструкцией не устанавливается: пакет задаёт интерфейс для его реализации. Сайт передаёт задания через уже существующую очередь GitHub; компьютер может скачать их обычным Contents API с правом чтения, а результат отправить с правом записи.

## Проверка транспорта демонстрационными изображениями

Только в отдельном явно обозначенном тестовом объявлении допускается `markers.test_only=true` и `payload.quality=design-preview`: это проверка доставки файлов, не одобрение качества карточек. Сайт показывает предупреждение, статус публикации не меняет. Производственные изображения с изменёнными символами/логотипом не проходят QA; для них нельзя выдавать успешную готовность. Не переносить это тестовое исключение на реальные объявления.

Большие JSON и фотографии читать через raw Contents API: поле content в обычном ответе бывает пустым. При неудаче чтения состояния не записывать поверх него локальную пустую копию. При редактировании после генерации отправлять исходники, не встраивать sourcePhotos с base64 в текст задания.


## Разделение текста, фото и внутренних нюансов

`cards.requested` содержит `payload.sourcePhotos`: только исходники, выбранные для следующей серии. `payload.item.photos` повторяет те же метаданные для совместимости. В обоих блоках нет `src`/base64: файл берётся только из `attachments`/`inbox`. Поле `defects` не передаётся в запрос на карточки и не используется в описании или надписях. Оно остаётся внутренним контекстом обработчика для честного ответа покупателю по прямому вопросу.

`cards.comment` — отдельное событие для фото: `payload.itemId`, `payload.comment` (`id`, `text`, `createdAt`, `scope: "cards"`). Оно не меняет текст, цену или статус объявления. Комментарий применяется только при следующей подготовке или исправлении серии изображений.

Сайт хранит `sourcePhotos` и `imageHistory` отдельно от текущей галереи. Текущая галерея содержит только выбранные изображения; первый объект всегда является главным. Отдельной кнопки «На обложку» нет: для смены обложки объект перетаскивают на первое место. Раздел «Все фотографии» показывает исходники и прошлые серии, новые серии выше старых. Короткое нажатие возвращает изображение в текущую галерею, долгое нажатие позволяет поменять порядок внутри набора.

Каждый новый приватный репозиторий обязан содержать папку `image-history/`. Постоянный путь файла: `image-history/<itemId>/<seriesId>/<NN>-<fileName>`. После успешной обработки локальный обработчик сохраняет туда исходники и готовую серию, а в `cards.completed` передаёт для каждого изображения `path`, `id`, `name`, `type`. Сайт умеет читать `path` напрямую. Файлы очереди в `inbox/` и `outbox/` после подтверждения можно удалять; история изображений остаётся доступна из `image-history/` до месячной замены репозитория.


## Смена месяца (MVP)

Законченные объявления, их фотографии, история и статистика не копируются в репозиторий следующего месяца. Новый месячный репозиторий начинает работу без них. Папка image-history создаётся пустой. Автоматический перенос или долговременный архив законченных объявлений пока не реализуются. Это правило не удаляет данные текущего месяца при обычном обновлении сайта.


## Все фотографии объявления
Все исходники и все полученные серии карточек сохраняются в imageHistory, включая текущую серию сразу после получения. Удаление из photos означает только исключение из активной галереи, а не удаление из истории. Интерфейс объединяет историю и sourcePhotos без повторов: новые серии первыми, четыре фотографии в строке. Лимит 10 применяется только к активной галерее, не к истории. Новая обработка должна сохранять предыдущую историю и ссылки на файлы. Правило действует внутри текущего месячного репозитория.

Активные photos (до 10) скрываются из сетки «Все фотографии», но остаются сохранёнными в истории. При исключении из активной галереи изображение возвращается первым в сетку как недавно возвращённое. Перестановка сетки не удаляет скрытые активные изображения из истории.
